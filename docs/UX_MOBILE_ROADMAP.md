# 移动端 UX 优化路线图

**基线版本：** `main@0422a0d`
**建立日期：** 2026-07-29
**跟踪 Issue：** [#88](https://github.com/chasingboy95/kagle/issues/88)

## 1. 改造目标

当前产品已经具备训练、记录、计划、语音、提醒和本地数据管理能力，但这些功能仍以“首页入口 + 多个抽屉”的方式叠加。下一阶段不增加训练算法，而是建立稳定、可预期的移动端操作结构：

1. 空闲态采用“训练 / 记录 / 设置”三个一级区域。
2. 训练页只回答“本次练什么、需要多久、如何开始”。
3. 记录页和设置页成为真正独立的页面，不再依附在训练首页下方。
4. 训练开始后隐藏导航和低频配置，进入沉浸模式。
5. 所有可编辑抽屉都有明确的草稿、应用和取消边界。

## 2. 当前问题证据

| 区域 | 当前行为 | 用户摩擦 |
|---|---|---|
| 训练记录 | 记录组件渲染在训练首页壳层底部，顶部仍出现无效入口 | 页面层级不清楚，返回路径不自然 |
| 底部入口 | “调整计划 / 声音与震动 / 更多”视觉同级 | 高频操作、偏好和设置被混成同一层 |
| 配置抽屉 | 步进器修改立即写入正式状态 | 关闭是否保存不明确，误触无法取消 |
| 更多菜单 | 提醒、引导和数据管理混放并直接展开 | 低频功能占据过多空间，像临时收纳区 |
| 小屏布局 | 辅助文字、统计卡和折叠面板较密集 | 320px 宽度和字体放大时阅读、触控负担高 |

## 3. 目标信息架构

### 一级区域

| 页面 | 核心内容 | 主要操作 |
|---|---|---|
| 训练 | 肌肉动画、当前计划摘要、预计时长、辅助状态 | 开始训练、编辑计划 |
| 记录 | 周目标、统计、列表、日历、趋势 | 查看详情、筛选 |
| 设置 | 训练计划、声音反馈、提醒、帮助、数据管理 | 进入二级设置 |

### 训练态

训练开始后不保留一级导航，只显示当前阶段、倒计时、动画、次数/组数、总进度和暂停/继续/结束操作。训练引擎仍是唯一时间源，本路线图不改变状态机或记录格式。

## 5. 自动化与真机验收矩阵

| 场景 | 自动化要求 | 真机要求 |
|---|---|---|
| 320×568 窄屏 | Playwright：核心入口可见、无横向溢出、页面可滚动 | iPhone 小屏或等效设备复验 |
| 390×844 常规屏 | Playwright：三页切换和训练核心路径 | iOS Safari/PWA、Android Chrome |
| 横屏 | Playwright：核心信息与操作持续可达 | 至少一台 iOS 或 Android |
| 200% 字体缩放 | Playwright：文本不截断，操作区可增高 | 系统字体放大复验 |
| 键盘与读屏 | 组件测试、axe serious/critical 为 0、焦点恢复 | VoiceOver/TalkBack 最终复验 |
| reduced motion | Playwright：非必要位移动画关闭 | 可选真机复验 |

自动化通过不能替代 iOS Home Indicator、安全区、系统时间选择器、VoiceOver 和 Android 系统返回行为的真机验证。涉及这些行为的 Issue 在合并后仍应在 `docs/REAL_DEVICE_TEST_CHECKLIST.md` 保留待验收项。

## 6. 设计约束

- 普通触控目标至少 `44 × 44px`。
- 普通辅助文字不低于 `12px`；不得仅靠低对比度表达状态。
- 简单选择可使用底部抽屉；复杂设置、记录和数据管理使用独立页面。
- 有未保存修改时，遮罩、关闭按钮和 Escape 不得静默丢弃。
- 危险操作不与主操作并排，不因视觉整理而弱化确认保护。
- 继续支持 `prefers-reduced-motion`、安全区、键盘导航和焦点恢复。
- 不新增医疗判断、动作识别、账号、云同步或新的训练算法。

## 7. 发布与回滚

每个阶段必须通过 `typecheck`、`test:coverage`、`lint`、`build`；影响完整路径时还必须通过 Playwright。单阶段失败时只回滚对应 PR，不回滚已经稳定的训练引擎、存储或 PWA 修复。

完成 #93 后，再进行一次覆盖 iOS installed PWA、iOS Safari 和 Android Chrome 的整体验收；真机未验证的项目必须如实保留为待办。
